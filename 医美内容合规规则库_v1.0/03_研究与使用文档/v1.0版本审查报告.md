## 5. 当前缺失内容

1. **官方处罚案例库为空**（0 条）。无行政处罚决定、无信用中国公示、无法院裁判样例，无法支撑"以案说法"与案例驱动校验。
2. **平台规则类来源为 0**：14 条来源全是法律法规/部门规章/监管指南，小红书、抖音、微信的社区规范、广告规则、电商规则、视频号规则均**未作为正式来源入库**（rule_platforms 的 source_id 因此全空）。
3. **部分法律来源缺失**：用户要求补充的《消费者权益保护法实施条例》《医疗广告认定指南》《广告引证内容执法指南》**已存在**（S0010/S0011/S0013）；**真正缺失**的是：
   - 《中华人民共和国个人信息保护法》（用户照片/病例/对比图/隐私）
   - 《中华人民共和国民法典》人格权编（肖像权/名誉权/用户案例）
   - 医疗器械分类规则/分类目录及监管公告（光电/射频/激光设备、器械宣传）
   - 药品/医疗器械广告审查相关细化文件
4. **来源证据未实体化**：04_来源证据下只有 4 份 Markdown 索引，没有按 `[source_id]_[名称]_[日期]` 保存的官方网页快照、PDF/HTML、页面截图、文件哈希与 metadata.json。
5. **AI 系统配套文档缺失**：无《合规规则库使用说明》《AI 合规检测流程说明》《AI 调用接口说明》；无 risk_scoring.json 风险评分模型。
6. **项目级文档缺失**：无 README.md；无 CHANGELOG.md（仅有 changelog.json 数据）。
7. **语义规则与示例偏少**：semantic_rules 仅 5 条（目标 ≥30），且正负/边界示例覆盖不足；rule_examples 仅 11/97 规则有示例。
8. **v1.1 元数据缺失**：metadata.json 仍为 v1.0，无 v1.1 版本与汇总重建。

## 6. 当前结构问题

1. **Excel 双表权威冲突（严重）**：`v1.0.xlsx` 仅含 ~23 规则 / ~20 测试（初始批），而 `batch2.xlsx` 含 97 规则 / 234 变体（与 JSON 一致）。两份并存且命名混乱，易误用陈旧表。建议 v1.1 仅保留**一份** Excel（由 JSON 权威源重建），废弃/归档旧表。
2. **平台规则缺来源关联**：rule_platforms 13 行 source_id 全空，违反 agent.md 第 8 节"每条来源须含 official_url/access_date"。平台维度规则目前不可溯源。
3. **测试集未执行**：200 条 test_cases 的 `test_result` 全为 `pending`，validation_report 中的"测试通过率"实际未计算（旧报告仅做了结构校验）。
4. **validation_report 浅且陈旧**：10 项校验未覆盖"规则示例覆盖率""平台规则来源空值""enforcement_cases 空库""测试执行结果"等关键质量维度；报告生成时间早于 200 条测试集与批量规则，结论已失真。
5. **04_来源证据目录结构不符新规范**：agent.md 原规划 7 个子目录（法律法规/行政规章/监管指南/平台规则/处罚案例/司法案例/案例线索），而用户 v1.1 要求调整为 6 个（法律法规/行政规章/监管指南/平台规则/官方案例/案例线索）。当前仅 `04_平台规则` 有内容，且为 Markdown 索引而非实体证据。
6. **示例与语义规则密度低**：86/97 规则无示例；语义规则仅 5 条，难以支撑"隐式语义风险""谐音/拆字/拼音规避"等检测场景。
7. **版本元数据未演进**：无 v1.1 的 metadata、无汇总主文件（v1.1）重建、无 CHANGELOG.md 记录 v1.0→v1.1 差异。

## 7. 修改建议（原则：不重新设计，保留结构与 ID）

1. **保留**：目录体系、全部模块、全部已有 rule_id / source_id / example_id / semantic_rule_id（不重编号）；新增数据一律用新 ID（如 R-A01-098、S0015…）。
2. **Excel 治理**：v1.1 以 **JSON 为唯一权威源**，重建单份 Excel（命名明确，如 `医美内容合规规则库_v1.1.xlsx`），将 batch2.xlsx 归档至 `06_版本管理/历史版本/`，删除根目录双表歧义。
3. **来源补强**：新增 ≥11 条来源，重点补"平台规则类"（小红书/抖音/微信各若干）与缺失法律（个人信息保护法、民法典人格权编、医疗器械分类）。每条补 official_url / access_date / page_last_updated / 产品线 / 账号类型 / 规则版本。
4. **平台来源回填**：为 rule_platforms 13 行补 source_id，使其指向新增的平台规则来源（S00xx）。
5. **案例库建设**：新增 ≥20 条官方核验处罚案例（C0001…），未核验的媒体报道放入 case_leads（CL0004…），绝不混入 enforcement_cases。
6. **规则与变体扩充**：沿 A01–A16 方向扩到 ≥150 规则、≥500 变体；每条新规则带来源、风险解释、系统动作、示例；禁止同义词拆条凑数（agent.md 第 12 节红线）。
7. **语义规则扩充至 ≥30 条**：覆盖保证效果/零风险/个案推导/未经诊断建议/容貌焦虑/不治疗后果/虚构资质/虚构数据/普通美容包装医疗/医疗包装消费/谐音/拆字/拼音/隐藏广告/软文等，每条含正/负/边界示例。
8. **证据实体化**：对每条正式来源生成 `[source_id]_[名称]_[日期].(pdf|html)` + 同基名 `metadata.json`（含官方 URL、查询日期、页面更新时间、文件哈希、页面截图路径）。
9. **AI 配套**：新增 03_研究与使用文档三份说明 + risk_scoring.json；根目录 README.md；CHANGELOG.md。
10. **测试与校验**：test_cases 扩到 ≥300（违规 100/正常 100/边界 50/平台特殊 50），并将 `test_result` 真正跑测后回填；重建 validation_report 覆盖 ID 完整/来源关联/JSON/Schema/重复/孤立/示例覆盖/平台来源空值/测试通过率。
